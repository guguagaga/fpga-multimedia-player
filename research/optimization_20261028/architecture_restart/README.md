# 从原始参考帧重新比较块表示（2026-10-28）

基准是未经块边颜色拟合的 Codec9 Q165；实验从原始 RGB565 帧重新编码。这里不是把压缩后的视频再次压缩。编码器源码在仓库根目录下的 `research/gradient_codec11`；旧编码器在 `host/video/src/encode_720p.cpp`。文件格式版本11为实验格式，v114不支持。

|方案|块编码预算（字节/帧）|PSNR（dB）|grid8残差梯度RMSE↓|
|---|---:|---:|---:|
|原 Codec9|165000|34.474465|7.425090|
|实验渐变块|145000|34.719705|7.073019|
|实验渐变块|155000|34.957966|6.893543|
|实验渐变块|165000|35.185015|6.730162|

这是4个时间点各3帧的合计结果：PSNR先合并MSE再换算；grid8为各片段指标均值。字节预算在Codec10式游程重打包之前，不等于最终SD文件大小或实际吞吐。代表色数量、帧率、原始分辨率均没有靠降低来获得这个结果。

145k平均结果较好，但110秒片段较原Q165低0.126dB，grid8也稍差；不能称所有场景占优。155k在这四段上PSNR和grid8均优于原Q165，平均提升0.484dB，预算下降约6.06%，适合优先验证。不得从少量样本推断整片或其他影片结果。

梯度块以四个RGB565控制色表示8×8区域，软件按率失真代价与原块模式竞争。独立RTL引擎利用横纵差分，每像素递推加法，不需逐像素乘法；这是已有研究原型，尚未接入生产解析器。当前使用分母8的权重，最后一行/列并非完全到达第二控制点，须保持编码器和RTL公式一致。每行有一个准备周期，不能把它当作全程每时钟一个有效像素。

下一步依次为：扩大到包含快速运动、文字、暗部和细纹理的独立片段；增加全片帧大小/最坏解码周期统计；在独立候选中连接字节解析、梯度引擎与背压；复用存储、音频和HDMI修复；做完整综合布线及并发音视频回归。用同一约束对比资源、最差路径、总违例、吞吐和实际观感。带宽下降不意味着高扇出或布线拥塞必然减少。

复核：准备protocol.json指定的4份原始输入，分别编译旧编码器和实验编码器，然后运行 `python benchmark.py --codec9 <旧编码器> --gradient11 <实验编码器> --input-dir <原始帧目录> --output <独立结果目录>`。输入媒体不随仓库发布。依赖Python与numpy。没有原始输入时只能审阅记录，不能声称复现画质指标。
