# 画面方向与行序约定

本文针对当前原生1280×720 Codec9/10路径。不要根据裸RGB565参考文件的直接预览去改卡上文件方向。

## 从原片到显示

1. `host/video/src/encode_720p.cpp`先按原片顺序完成块级颜色搜索和率失真分配，再反转块行及块内行，存成底向上行序。这保留颜色搜索的确定性。
2. Codec10仅把相邻同色块合并为运行长度，不改变原有像素或方向。
3. FPGA块解码器与raster模块恢复的是文件中的行序。两个RGB565像素按原有左右顺序打包成一个32位显存字。
4. 帧写入器按底向上地址写入。对第y行第x个打包字，测试核对的帧内地址是 `(719-y)*640+x`。因此显存中按显示顺序读取时，画面恢复到原片上下方向。

水平顺序没有在这条720P编码链上额外镜像。修改上下行序、翻转左右像素或交换32位字中的两个RGB565像素，是三种不同操作，不能互相替代。

## 软件预览

本地 `reference.rgb565` 用来核对解码输出，保持文件底向上行序。直接按顶向下图像显示会倒置。制作最终显示预览时要应用与帧写入器等价的行地址映射，垂直反序一次；不能把这一步后的预览再写回SD媒体。

软件解码预览、RTL逐像素核对和显示器上的实拍图是不同证据。当前720P仍需实板确认显示器锁定、方向、边缘与音画同步。

## 图片路径

图片有底向上BMP、顶向下BMP和QOI，分别根据格式头或格式约定传递 `write_top_down`。原生800×600图片旁路和通用缩放路径必须同时保留这一语义。图片等比例适配、黑边和通用低分辨率放大属于另外的功能，未在本轮改变。
