# RAW块范围位打包研究

日期：2026-10-27。代码与测试由本工程编写；未引用新的开源实现，也未虚构外部项目的更新日期。已有参考资料与访问日期见REFERENCES.md。

## 为什么先研究RAW块

对现有720P Q165全片6330帧/422秒、91,152,000个8×8块统计，RAW仅占4.015%的块，却占47.925%的视频payload。现有Codec10实色游程相对相同重建像素的Codec9已节省58,852,855字节（5.6375%）。继续压缩RAW存储有机会给读卡和FAT访问留余量；节省的预算也可用于后续离线编码器增加细节。

## 方法与格式提案

保持8×8块位置、RGB565像素和现有token不变，仅尝试将RAW分成四个4×4象限。分别计算R/G/B通道最小值及最大偏差，按偏差所需位数存残差。块头假定使用实验opcode0x86，随后一个字节以每象限2bits描述模式。模式00保留32字节原始象限；01存RGB565最小值2字节、三通道位宽字段2字节、16个像素按R/G/B顺序LSB优先打包的残差。每象限不划算则原始存储，整块不短于129字节则回退既有0x83 RAW。

没有预测依赖或跨帧状态；当前像素逐一精确重建，仍保留RGB565原有量化和旧编码器的块表示误差。位宽由range.bit_length()确定，通道范围可不同。不涉及训练数据泄漏或学习模型。

## 已完成的验证

固定步长601、offset317抽样6089块，覆盖5743帧。4×4范围候选实际打包并逐像素解码一致，样本RAW字节减少17.8128%；8×8范围仅减少5.9367%。这些样本不是随机置信区间，不能直接外推全片收益。合成11005块/704320像素包含平坦、受限范围及随机RGB565，往返一致；还检查短包、未知模式、非法位宽/越界等拒绝分支。

全片已实际编码并解码核对3,659,731个RAW块、234,222,784像素；节省83,285,642字节，占原RAW字节17.6413%、全片payload 8.4545%。这是保持当前RGB565重建像素不变的离线结果，尚无RTL性能结论。

| 指标 | 现有Codec10 | RAW范围候选 | 字节减少 |
| --- | ---: | ---: | ---: |
| 平均单帧/B | 155,623.81 | 142,466.52 | 8.45% |

## 尚未进入生产的部分

**现有生产FPGA解码器拒绝0x86；不要把该格式写入SD卡，也不要把研究结果当作可下载bit。** 本研究输出JSON统计、单块Python编解码和独立RTL原型，不生成可播的新格式电影。

独立`experimental_raw_bounds_decoder.v`已做1003个有效块、8个坏包、100次取消/重启，随机式确定性输入空隙、暂停和输出回压下核对70,592个像素。该原型先存一块64×16bit重排缓冲，再输出行序像素；残差分R/G/B三拍提取，读取同步存储与输出交替，因此并非每拍一像素的高速实现，也没有综合面积和最终STA结论。不能把它直接接到生产播放器就宣称吞吐更好。下一阶段应先明确共享存储/双端口与有效像素率，再做资源和全链路预算。

下一步先确认整机时序，再为新token评估位缓存、可变移位器、通道加法和象限重排的面积/关键路径。解码目标是流式、一周期最多一个像素，不能为了减少文件字节引入更长的像素解码瓶颈。需要加入坏包、取消/重启、扇区边界、随机回压、完整高码量窗口、原语和最终布线回归。稳定版与实验版须使用不同容器版本/格式声明，防止旧bit误读。

此编码没有直接提高画质，也未证明提高帧率。若全片字节收益成立，可在后续同带宽编码器中重新分配RAW预算，再与原视频做PSNR/SSIM及文字、色阶、运动细节对比；不能仅用体积变化替代观感评估。

## 可复现命令

在research/raw_bounds目录执行（Python标准库，无第三方包）：

```powershell
python -X utf8 experimental_raw_bounds.py
python -X utf8 test_experimental_raw_bounds_rtl.py
python -X utf8 analyze_codec10.py YOUR_CODEC10.VID --report fullfilm_rate_analysis.json
python -X utf8 explore_raw_lossless.py YOUR_CODEC10.VID --report raw_lossless_exploration.json
python -X utf8 evaluate_raw_bounds_fullfilm.py YOUR_CODEC10.VID --report raw_bounds_fullfilm.json
```

输入是用户合法持有的现有Codec10视频。版权媒体不随仓库分发。results目录保留本次结果及输入SHA256；全片报告含每帧字节数，可检查高码量窗口。它们不包含实板、I2S、SDRAM、物理SD延迟或STA验证。
