# 稳定性优化路线

v182冻结为用户报告正常的基线。后续源码、约束、bit及媒体采用独立版本与哈希，不覆盖稳定版。

1. **状态切换与故障恢复**：审查音乐/图片/视频共享读卡控制，测试播放与暂停时进入/退出视频、连续按键、切歌和读卡超时。每个发现先建立复现测试，再修改RTL。
2. **异常交互**：核对缺卡、无可识别文件、文件头损坏、FAT断链/循环、SD读超时是否提供可识别状态及重试/返回路径。界面先显示中性的状态文字，队名/logo等待素材。
3. **时序与约束**：分析v182最差路径、逻辑级数、布线/扇出贡献；保持原约束，不通过隐藏路径或调低要求伪装改善。候选必须有新进程STA及功能回归。
4. **交付复现**：验证生产文件映射、工具配置、README和bit/media哈希；更新组员可执行的构建与测试入口。
5. **后续性能**：以上成立后才继续更高吞吐、720P30或新块表示；同时比较画质、帧间隔、音频连续性和资源，不能仅追求某个单项数字。

本轮内部完成标准：已有问题无定向回归失败；有界错误处理和状态切换测试通过；候选独立时序不劣于基线；所有交付可核对。实物最终验收仍需要用户运行，不能由仿真替代。

建议上板补记：完整播放3轮；播放和暂停状态各退出/进入10次；冷启动/复位各10次；低/高分辨率图片与歌曲交替切换；记录具体bit哈希、卡、现象与持续时间。数值是待执行计划，不是既有通过结论。
