# 后续优化顺序与验收门槛

2026-10-27。本文件给接手组员使用，所有实验须保留源码快照/哈希、原始报告和失败记录；最终状态见VALIDATION.md及release_status.json。

## 1. 先收敛当前720P整机

v56综合17774/19600 LUT、12018 FF、BRAM9K53/64、BRAM32K12/16、DSP24/29。最终setup−2.287ns、729个违例端点，hold+0.021ns、0个违例。相比v55减少199 LUT、114 FF，setup改善0.997ns，但仍不合格。v57进一步按独热状态位分派，最终setup−9.095ns、773个违例端点、hold+0.030ns，效果恶化，拒绝替代v56。当前交付保留v56，v57放私有实验源码与报告供追溯。

v56最差路径是bmp_len_cnt到图片主状态，12.035ns数据延迟中布线占8.561ns（约71%）。同时有图片状态到头字段使能、FAT mapper当前簇到assembled使能等路径。后续优先减少共用控制锥的扇出和长距离布线，拆分计数边界/文件末尾与请求使能；每项改动独立候选。对需要最后一个字节参与判断的条件，必须使用当前完整值或显式增加等待阶段，不能盲目加寄存器。

v53曾把根目录next簇合法性整体寄存，在root cluster127的FAT项位于扇区bytes508..511、结束紧随最后字节时漏检高字节。root_tail测试抓出0x01000009越界回归，v54只寄存稳定最大簇边界并恢复当前next判断。这个失败已保留，后续流水不能删除此测试。

不要继续盲目堆seed，或加false/multicycle path使报告好看。时钟组沿用原工程，部分外部IO尚缺delay约束，系统接口裕量仍需独立确认。若继续优化可考虑更大结构拆分，但不能削掉赛题要求的图片/音频/频谱能力而声称功能完整。

## 2. 720P全片板测

先获得对应源码setup/hold零违例的bit，再验证aigo F156P1锁定720p30、6330帧/422秒全片及循环、音画同步。卡上配对音轨仍PCM；IMA候选尚未替换，不能把IMA仿真吞吐直接当卡上现状。

真实IMA+高码量三帧在模型中逐视频像素/PCM样本通过；九帧历史模型也通过，但都不是422秒全片RTL仿真。显示发布由30Hz和就绪控制，某些帧可延迟100ms；不能只看65ms解码间隔就宣称持续15fps。实板应记录每分钟同步、暂停继续/退出重进、播到末尾、卡延迟及碎片跨簇。

FAT支持1..128扇区/簇，但CMD18不跨簇、缓存最多16扇区。SPC<16及极端碎片会增加命令和FAT查询，逻辑兼容不等于吞吐保证。旧800×600 bit不能播卡上新720P文件。

## 3. 再决定新RAW格式是否合入

全片精确范围打包节省视频payload8.4545%，但最重单帧仅改善约1.12%。独立RTL原型先缓存64×16bit再输出，残差分三通道处理，并不是最高吞吐实现。它当前不在生产源码层级和容器中，旧解码器拒绝0x86。

先为原型做独立综合和周期统计，衡量每帧新增解码周期、重排存储与可变移位器成本，再设计与现有raster的接口。可以复用现有块重排存储、避免再加整帧缓冲；若要求不增加存储，应重新设计token像素顺序，并使用新的显式格式号。不要沿用旧Codec10头隐藏不兼容token。

精确RGB565保持意味着画质不变。提高画质需要在节省的字节预算上重新做离线率失真分配，以同预算、同分辨率/帧率比较原视频误差和实际观感；测试集至少涵盖HUD文字、色阶、草地纹理、团战及镜头移动，避免只针对一个片段调参。先保画质和分辨率，再提高帧率。
