# 多视频播放候选版 v183

基线：已上板确认的 v182；稳定基线和其 GitHub Release 保留。
本分支 `rtl/` 为分模块候选源码，通过 `project_manifest.json` 还原参与构建的工程路径。
内部时序和功能仿真已通过，仍需用户上板验收；不要混用历史中间 bit。

## 操作

视频模式下：扩展板 KEY1 下一部，KEY2 上一部，KEY0 暂停/继续，KEY3 退出视频。
KEY2 在非视频模式下仍执行原来的切图功能。默认播完自动下一部，末部循环到首部。
板载音乐双击事件在视频模式下切换自动续播开关；关闭后停留末帧，仍可手动切换。
切换期间再次按上一部/下一部会被忽略；待新视频开始后可继续操作。
切换暂停中的视频时，新视频从开头播放。

这里的“自动下一部”必须等最后一帧到达显示边界、跨时钟域发放音频额度、最后的 PCM 消耗结束。
切换会经历停止旧读卡、选文件、音频排空/淡出、重新预读的过程，不是无缝接播。

## 卡上文件

在 FAT32 根目录放最多四组短文件名（8.3）：

| 编号 | 视频 | 对应音轨 |
|---|---|---|
| 1 | M1_VIDEO.VID | V1_AUDIO.VAU |
| 2 | M2_VIDEO.VID | V2_AUDIO.VAU |
| 3 | M3_VIDEO.VID | V3_AUDIO.VAU |
| 4 | M4_VIDEO.VID | V4_AUDIO.VAU |

按前两个字符配对，M/V 和扩展名不区分大小写；后缀可以不同。
现有 M1_C10.VID + V1_AMIYA.VAU 属于第一组，可以继续使用。
跳过没有配齐 VID/VAU 的编号，支持 1、4 这样的稀疏编号。
同一个编号存在两个 VID 或两个 VAU 时保留目录中先发现的文件；因此不要放重复编号。
旧文件可在电脑端改成 `.BAK` 保存，不能只把同组旧文件改成另一个 `.VID` 名称。
文件可以碎片化；继续使用原有 FAT 链读取器。根目录扫描本身也支持碎片链。
没有任何 M1..M4 视频时保留旧式首个 VID+VAU 的单组回退；本候选不支持无音轨的视频自动轮播。

## 编码和配套音轨

继续使用 v182 发布包里的 `encoder/encode_video_codec12.py`，输出仍是 1280×720、15fps、Codec12。
这次增加播放列表，没有提高或降低画质、分辨率及帧率。
该工具只编码视频。音轨必须来自同一原片的同一时间范围，PCM 48kHz/单声道/16位。
读取 VID 头偏移 16 的小端 32 位帧数 N 后，配套音轨应恰好为 N×3200 个样本。
FFmpeg 的音频处理示例（将 SAMPLES 换成实际样本数，明确使用 WAV 容器）：

```powershell
ffmpeg -i input.mp4 -vn -ac 1 -ar 48000 -af "apad,atrim=end_sample=SAMPLES" -c:a pcm_s16le -f wav V2_AUDIO.VAU
python host/video/playlist/prepare_playlist_pair.py --video output.VID --audio V2_AUDIO.VAU --slot 2 --output D:/codexworks/staged_playlist
```

准备工具拒绝覆盖已有编号，检查格式与音轨时长，复制后逐文件核对 SHA256。
格式一致不代表内容时间轴匹配：不同原片/偏移生成的音轨仍会导致音画错误。

## 上板验收样本

`host/video/playlist/make_playlist_demo.py` 生成原创纯色/音调样本：红440Hz、绿660Hz、蓝880Hz、黄1100Hz，各2秒。
生成位置应为电脑上的新目录。不会自动修改 SD 卡。
这些文件便于判断配对及自动轮播顺序，码率很低，不能替代真实电影的吞吐量与画质测试。
复制前先处理卡上原有同编号文件，避免目录中出现两个 M1 或 V1。

建议验收：四组循环10轮；连续手动前后切换；暂停后切换；自动与手动交替；退出视频恢复原歌曲；
再用真实长片测试音画同步和尾部切换。测试时记录 bit 的 SHA256、卡上文件清单及结果。

## 验证边界

目录、切换控制、实际解码器/FAT 链、720P 图像、音频 FIFO/淡出/I2S 分别有仿真证据。
小帧测试覆盖大量边界，真实720P测试覆盖像素/吞吐；二者不互相替代。
只有 fresh routed STA 报告才能确认本轮内部时序；综合成功不等于时序通过。
独立 STA 仍沿用稳定版本约束及其外部 IO/CDC 签核限制。

## 源码分工与状态边界

| 模块 | 本轮职责 |
|---|---|
| `video_catalog.v` | 缓存四组视频/音轨起始地址，按编号配对，寄存可用位图，重复编号保留第一项 |
| `video_playlist_ctrl.v` | 停止旧会话、等待读卡释放、搜索下一有效编号、选音轨、等待 ready 先降后升 |
| `video_eof_guard.v` | 等待最后帧的显示事件、跨域音频额度生效及消费完毕；暂停时不自动切换 |
| `fat32_list.v` | 在原目录扫描基础上发出每个 VID/VAU 的文件名前缀和起始扇区事件 |
| `video_player.v` | 按文件头声明的帧数有限播放，最后提交之后停止申请下一帧写入 |
| `top_tf_hdmi_audio.v` | 模式按键、目录选择、音轨切换、显示边界与 EOF 连接；冻结后台歌曲索引 |

控制顺序：PLAY → STOP → SEARCH → SETTLE → SELECT → WAIT_LOW → WAIT_HIGH → PLAY。
STOP 期间不改变选中文件地址，直到旧视频 SD 请求及授权均解除，防止 FAT 映射身份在读卡中途改变。
音轨选择需观察 ready 下降再上升，并等待淡出/排空状态结束；不直接把旧 ready 当作新音轨已准备好。
选择超时约2秒，进入停止的失败状态，可再按前后切换或退出。坏视频头仍由解码器拒绝，
本版不承诺自动跳过所有损坏媒体；编号缺少音轨时则在目录级直接跳过。

EOF 中“最后提交”与“最后显示”分开判断。最后新缓冲在显示边界被观察到后，
等待64个 SD 核心周期，超过当前固定时钟下的音频额度及返回标志同步延迟；
再确认最后一帧确实获得过非空音频额度，最后等待额度耗尽。
如果未来更改核心/音频时钟比，必须重新核对这一跨域等待上界，不能只复用当前测试结论。
