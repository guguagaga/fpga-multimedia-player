# v114 音频异常防护测试版

基于已能出画面的 v113，保持 1280×720/60Hz HDMI、原文件帧率、音频时钟、视频解码通路和画面方向。仅修改音频扇区读取和顶层异常恢复/故障显示。720p60 是显示刷新率，不代表视频60fps。

## 当前结论

这是测试版，尚未实板验证。综合和布线完成，但正常时序门禁仍拒收：setup WNS -1.980ns，hold WNS +0.027ns，setup失败端点 338，hold失败0。占用 95.28%、RAM65、DSP24。未放宽SDC，不能叫稳定版。

v113的“音频突然从头、视频继续”能够由原100ms就绪看门狗造成；测试已复现这一恢复策略问题，但实板上最初导致音频掉就绪的具体原因尚未确证。不要把本版描述为音画问题已经彻底解决。

## 修改

1. 等待SD仲裁时不计音频自己的I/O超时；已授权交易的备用超时300ms，晚于FAT映射器250ms的物理I/O超时。仍保留明确的错误终止。
2. 只有完整512字节扇区才发布给解码器。短读结束后，在原LBA最多重读2次；不推进解码位置、不发布残缺RAM。取消、超时或重试耗尽不继续发请求。
3. 已确认的视频音轨发生故障时，不再悄悄从头选轨。真实不可恢复错误仍可能停声/停画，需要用户退出视频再进入；这项措施是防止错误恢复造成错位，不是把静音算作成功。
4. 视频模式下左起第5位数码管锁存音频故障代码：0=未记录，4=FAT扇区长度错误，5=物理I/O超时，6=提前链尾，7=坏簇，8=链自环，F=音频读取/解码本地错误。退出视频清除。左两位仍为十六进制帧率：0F=15、0E=14、0D=13、0C=12。

## 验证

详见 STATUS.json 和 reports。扇区短读/取消/授权等待/超时晚到、旧新恢复策略对照、碎片FAT下PCM/IMA/QOA单双声道42轮切换、坏簇后人工重新选轨、真实顶层选轨与淡出控制207次来源/PCM检查均通过。

长音轨结果：True；Q165联合颜色拟合样片像素/PCM结果：True；Q185样片像素/PCM结果：True。逐字节正确与持续帧率是不同指标，显示间隔结果另见 STATUS.json 的 video_cadence；Q185不作为本次SD默认。pending或false均不能写成通过。大范围仿真使用真实RTL和行为卡/缓冲模型，不等于物理SD/HDMI/外部存储电气验证。

## 上板顺序

用户自行JTAG临时下载 bitstream 中的文件。复位后先确认首图；进入视频，用手机秒表同时计时，播放完整约7分02秒，尤其观察3分钟附近。若停声或声音重播，记录墙钟时间、屏幕进度和六位数码管；再测试暂停/继续及退出/重进。视频质量文件可在v113/v114解码，音频异常防护仅在v114中。
