# 原生720P设计与算法

基线是同学的快速读图链路与v19集成版本，原视频常用有效画面800×450、800×600帧缓冲。v22将视频主链升为1280×720。

## 内存与吞吐

- 921600像素/帧；RGB565两个像素打成一个32位字，每帧460800字，三缓冲5,529,600字节，适配8MiB SDRAM。
- 写侧每行640个字；翻行时不交换同一字内两像素，保留方向。读侧按相同顺序解包。
- 8KiB压缩字节FIFO显式使用2块32Kbit RAM，相邻字节独立写入，避免自动推断消耗过多9K RAM。
- HDMI总时序1650×750，标称像素时钟37.125MHz、串行185.625MHz。F156P1对720p30的实际锁定待板测。
- 音频消费样本数驱动画面预算；48kHz下提前1920样本即40ms，兼容30Hz扫描。视频帧更新15fps，输出扫描30Hz。

## 离线算法

8×8块建立实色、4个4×4代表色、双色调色板、RGB565原样块等候选，用加权颜色误差评估，构造率失真凸包，按每增加字节可减少的误差分配帧预算。双色搜索结合多种种子和迭代细化。Codec10实色游程重打包保持Codec9重建像素完全相同。

Q145/Q165表示每帧Codec9预算145000/165000字节，并非JPEG质量或帧率。原422秒视频已各编码6330帧；全片结构和91,152,000个块规范重打包一致性已校验。媒体不随公开源码分发。

5个时间点×3帧软件重建比较：旧800×450 Q125放大31.63dB；原生720P Q145为32.64dB；Q165为33.12dB。PSNR基于RGB565参考，不能代表板上截图或消除所有块感。

## 历史v22时序修改（非当前结论）

图片高水位反压寄存化，原512字FIFO在256字预警，保留流水余量。数码管字形在100MHz下降沿采样后交给50MHz扫描。WAV通道/块长分类寄存化并用低位判断对齐，FAT短文件名改用固定字节选择。不增加假路径掩盖违例。

## 验证边界

视频主链v21六帧真实码流逐像素仿真通过，稳态提交间隔6666666个100MHz周期；三帧卡顿/暂停压力测试通过。RAM模型58,315次核对通过；长样本预算12660帧授权相当于844秒媒体时间。它是加速调度测试，不是整片RTL仿真，也不是板上耐久测试。
v22视频主链未改，修改后的音频头检查、多模式切换、目录等价、数码管动态采样已回归，图片链路重新测试。最终时序与板测状态单独记录，不能从局部回归外推整个系统通过。

## 当前FAT簇链快照

历史v21/v22结果保留版本边界；当前已经加入碎片FAT映射、视频格式参数化和后续资源/时序改动。数码管现为100MHz同域正沿扫描，取代历史半周期方式。当前资源、最终布线与真实音视频联合模型见[TIMING_OPTIMIZATION.md](TIMING_OPTIMIZATION.md)及[VALIDATION.md](VALIDATION.md)，不能沿用旧报告作为新快照的稳定性结论。
