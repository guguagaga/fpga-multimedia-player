# 音频退出恢复与图片自适应设计说明

## 验收行为

进入视频前正在播放的歌曲，在退出视频后重新从头播放。无论退出时视频正在播放还是已暂停，均需排空旧音轨、重新装载原歌曲头部并恢复音频输出。

图片以保持比例、完整显示为原则，适配到 1280×720 画布。相同宽高比的不同分辨率图片占用相同区域：4:3 为 960×720，16:9 为 1280×720。不会将低分辨率源图变成真实高分辨率图片。源文件自带黑边仍然是内容的一部分。

## 文件与职责

| 文件 | 修改职责 | 必须保持的约束 |
| --- | --- | --- |
| `user_source/hdl_source/media_player.v` | 将 FAT 文件身份与真正开始的 reader 事务绑定 | 选歌请求不应提前改变未完成请求的文件基址 |
| `user_source/hdl_source/compressed_audio_reader.v`（v172） | 将已提交的 sector_l 暴露为 file_base_lba | start 之前旧事务必须完成；不能用 pending_sector 替代 |
| `rtl/img_scaler.v` / image_fit_720p | 计算显示区域，进行最近邻缩放、居中及补黑 | 读写反压下像素次序不变；每帧完整输出 921600 像素 |
| `user_source/hdl_source/SD/bmp_read.v` | 接收小图、传递原图高度、跳过 BMP 行尾填充 | 快速跳行后的流高度与原始宽高比需分开传递 |
| `user_source/hdl_source/SD/sd_card_bmp.v` | 接入统一缩放器、协调高水位与显示提交 | 不得在完整写帧之前发布新显示帧 |
| `user_source/hdl_source/top_tf_hdmi_audio.v` | 使用缩放器输出的完整 720P 光栅 | 视频占用期间不得把图片数据送入视频写帧链路 |

## 音频事务顺序

1. 接收切换意图，但旧请求继续使用旧文件身份。
2. 完成旧 SD 事务并等待相关读取器空闲；输出端按原有淡出/排空协议结束旧样本。
3. 开始新读取事务时，提交歌曲基址及播放参数。
4. 重新读取歌曲文件头，恢复采样链路和淡入。

原版本把第一步的 pending_sector 直接暴露给 FAT mapper，可能让旧视频音轨请求被解释成新歌曲内的远端偏移。这个错误已经通过真实 mapper 定向仿真复现。修复并不依赖用户额外按一次播放键。

## 图像算法

令原图比例尺寸为 W×H，输出画布为 1280×720。若 W×720 >= H×1280，则显示宽为 1280，高为 floor(H×1280/W)；否则显示高为 720，宽为 floor(W×720/H)。极窄比例的显示维度至少为 1。

比例除法只在每张图片开始时用逐次减法计算，不在像素组合通路中放可变除法器。取样坐标由累计余数推进，等价于 floor(输出坐标×输入维度/显示维度)。一条已缩放行保存到块 RAM，放大时可以重复输出；其余区域输出黑色。

输入 FIFO 为 512 个 RGB888 像素，高水位为 256，给正在进行且不能立即截断的 SD 扇区事务及流水级留出空间。行缓存显式采用 2048 深度、11 位读地址和块 RAM 属性，避免综合为大量分布式存储。

BMP RGB888 的每行长度按 4 字节对齐。行尾填充字节不构成像素，必须在颜色拼接之前跳过。原快速路径仍可仅选取 480 条源行，但用于适配比例的高度始终是原始高度。

## 未采用的 v173 目录判断实验

fat32_list 在提交 DBR 几何时保存本簇的末扇区序号：total 非零时保存 total-1，total 为零时保存零。在目录扇区完成时，原判定 done+1 >= total 等价为 done >= last。这使关键路径不必串联加法与比较，也没有新增扇区等待状态。

65536 组计数与总量组合已验证等价；真实目录仿真覆盖 1/2/4/8/16/32/64/128 扇区每簇、分区偏移、第二份活动 FAT，以及自环和坏簇。该改动只针对 v172 布线报告中的具体违例路径；完整物理实现未通过，因此后续 v176/v177/v178 不采用该改动。

## 验证边界

图像测试以逐像素参考公式核对，不只检查“有输出”。除适配器测试外，还联合真实 BMP/QOI 解析器和图片控制器，并通过异步帧写模块检查地址、像素与显示提交顺序。按键测试包含加载中重复请求、视频占用/恢复、转场确认缺失和周期修改，使用加速的用户界面计时参数。

音频联合仿真使用真实 reader、异步 FIFO、sample builder、淡出与 I2S，SD 扇区和显示授时为模型；FAT 错配另用真实 FAT mapper 定向验证。模拟 PCM 常量样本用于区分来源，不代表完整歌曲听感测试。

最终交付以对应版本的功能报告、源码哈希、完整布线报告和独立进程复核为准。SD 卡读写电气、显示器和实际音频输出仍需上板验收。v167 原有外部 I/O 与 CDC 约束边界没有被扩展为完整板级签核。

## v178 频谱关键路径优化候选

实际违例经过 bar_index 索引加法、grad_lut、alpha 混合以及输出选择。v178 把 grad_lut 计算提前到已有几何寄存器边界之前，使寄存的调色结果与原来的 bar_index_q、rgb_q 同周期对应。复位色保持 0x0000FF，与原 bar_index=0 查表一致；没有新增输出延迟。完整两帧及复位、使能切换共 1873719 周期，RGB、DE、VS、读地址与 v176 相同。物理结果单独判断。

## 物理流程的独立验收

TD 运行时执行 set_clock_uncertainty 可能无法解析对象；使用独立优化 SDC，经 read_sdc 载入，在实际 placed timing 报告里核对数值。SD/video 额外 setup 目标仅用于优化，生产 timing.sdc 和实际 PLL 不变。

同进程 clear_sdc 后更新时序可能产生失真时钟结果，因此最终验收必须另起工具进程，在第一次 update_timing 前加载原始 timing.sdc。审核时钟集合、频率、setup/hold、TNS、端点数、覆盖率及 DRC。过程目录报告仅用于诊断，不作为最终签核替代。


## v180 图片文件身份连接

`SD/sd_card_bmp.v` 的 `file_base_lba` 必须始终驱动为本次 `load_sector`，顶层将其送到共享 FAT mapper。它与缩放器数据接口无关，替换 scaler 时不得删除。当前控制器在上一加载完成或视频锁清理后选择新文件；测试需同时验证事务请求、文件基址和实际物理读扇区，不能只用直接逻辑扇区应答替代 FAT 通路。`tests/image_fat_memory_*` 增加实际样本与真实异步 FIFO 的逐像素/逐地址验证；板级时序、电气验证仍独立。
