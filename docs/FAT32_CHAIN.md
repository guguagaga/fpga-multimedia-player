# FAT32簇链读取（2026-10-27）

## 为什么必须补齐

旧版只从目录取得首扇区，之后按LBA+1连续读取。Windows复制时只保证文件逻辑内容，可能分配多个不相邻的簇；普通电脑按FAT链跳转，旧RTL却会读到其他文件/空闲区。哈希正确与单段连续是两件事。新版在仲裁器与物理SD控制器之间加只读映射层，媒体客户端仍使用“首簇LBA+文件内扇区偏移”。

## 数据路径

目录挂载导出FAT起点、数据区起点、每簇扇区数与最大簇号。图片owner0、音频owner1、视频owner3各有文件基址/簇下标/簇号游标；文件切换或向后seek会从文件首簇重新走链。owner2用于目录与FAT的原始扇区读取，避免递归映射。

支持512字节扇区、每簇1/2/4/8/16/32/64/128扇区、MBR首分区或超级软盘、ExtFlags指定的活动FAT。簇号仅取FAT32低28位；根目录自身也沿簇链继续扫描。仍仅收集根目录、四张图/八首歌，取第一个VID及VAU；未实现任意子目录浏览、exFAT、FAT16或写文件。

## 资源与吞吐

一个512字节FAT扇区缓存与三个媒体游标共用16位元数据块RAM。连续簇号通常一扇区可缓存128个FAT项；极度碎片的链可能频繁替换此缓存，吞吐取决于实际卡延迟。

新CMD18预读只在当前簇至少剩16个物理扇区时启动，避免跨碎片边界。已有预读缓存按真实物理LBA精确匹配，边界处禁用新预读仍允许命中旧缓存。每簇不足16扇区时使用单扇区读，不能承诺最坏碎片布局仍达到720P15fps。

簇/扇区换算采用逐拍移位，最多增加14拍；100MHz下约0.14us，远小于一次SD读取。频谱工作存储也移入BRAM，带写后读前递，柱高和衰减与旧版对比，仅提交推迟1拍（约27ns）。

## 错误与恢复

识别未挂载、非法首簇、提前EOC、坏/空闲/越界簇、明显循环、跳转步数上限、FAT扇区长度错误、传输无进展超时。默认超时250ms/100MHz；音频源自身另有100ms看门狗。长循环按步数限额终止，并非即时全链去重。

错误随事务owner路由：音频报track_bad；视频停止本次会话，退出再进入可重试；图片丢弃未完成帧，保留上次完整画面，手动下一张或重新初始化后重试。SPI超时重置物理控制器并重新扫描目录。没有新增中文错误提示页。

这是只读文件访问，绝不改写SD的FAT表。未加入目录file-size的独立边界校验，媒体长度由各格式头控制；损坏文件与热插拔仍需实板验收，不能宣称恶意文件隔离或任意卡兼容。

## 验证

mapper合成测试覆盖八种簇大小、三种媒体交错、随机/向后seek、同owner换文件、raw旁路、错误后恢复。另有根目录碎片/活动FAT测试；真实QOA/IMA/PCM字节/采样参考、三帧真实720P逐像素/地址、BMP/QOI完整图像，均使用重排物理簇的卡模型。每项最终结果与来源哈希见本地报告；改动版本不同的证据必须单独注明。
