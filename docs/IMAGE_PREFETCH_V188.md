# v188 提前预读实验结果

v188尝试在音频FIFO水位达到6144字节时，允许图片预读早于周期过半；低水位仍使用R3的半周期保护。预读收益在加速仿真模型中确认：相同QOI320x240、相同SD服务延迟和音频消耗时，R3基线第一次切换约5,546,313周期、第二次11,059,797周期；提前预读第一次4,000,053周期、第二次8,000,106周期，等待减少约27.9%。3帧共2,764,800像素均通过，音频FIFO最低约6096，未欠载。

该数字来自固定加速模型，不能直接换算成实板毫秒或承诺任意SD卡提速。实际控制回归覆盖低水位回退、预读中视频锁、预读失败恢复、40次手动切图和10次轮播开关；长事务模型12次图片占用通过，最低FIFO3165字节。QOI连续加载的R3残留done缺陷已复现并修复：修复后连续5次加载和异常尾标记后重启通过。

## 为什么暂不交付

提前预读候选的独立新进程生产SDC检查失败：setup WNS **-1.343ns**，TNS **-10.449ns**，17个违例端点；hold **+0.024ns**，覆盖96.32%。原因是新增提前准入控制和关联控制路径改变了拥塞/关键路径。v188没有发布、没有上板、没有覆盖R3。实验bit和数据库保留在`D:/codexworks/image_prefetch_v188/fixed_qoi`，严禁烧录。

## 下一步

先保留R3作为唯一验收版本。若继续研究，应把提前准入改成更低扇出的事件/水位快照，或复用现有`image_priority_q`/音频水位同步，避免把新的比较器和多条件组合放进SD时钟路径；每次仍需完整生产SDC独立STA。不能仅凭仿真切图周期改善就放宽时序。


## v188c 保守水位结果

将提前准入从14位`fifo_usedw >= 6144`比较改为复用已有`fifo_lvl == 3`单比特状态后，综合LUT从失败版约17778降到17749，但独立STA仍为setup **-0.030ns / 1端点**、hold +0.032ns。seed12换布局仍为同量级，说明当前架构的提前准入路径仍然固定压在SD时钟边界上。v188不交付、不上板，R3保持唯一基线。

结论：预读调度的功能收益约27.9%已在模型中复现；要让它合法，需要把提前准入从SD控制路径移出（例如低频事件/独立时隙调度、在现有仲裁器内部复用既有请求状态，或增加一拍且重新证明事务安全），不能继续只换布局seed。
