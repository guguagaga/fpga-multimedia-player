# R3之后的图片切换延迟优化

2026-10-31。根据用户上板反馈和当前RTL静态检查制定；以下均为后续方案，未修改已签核R3。

## 已确认与未确认

用户报告交互改善，但短周期仍受最低读取时间限制。没有实测阶段计时数据，不能断言全部瓶颈都在SD卡。R3的AUTO显示已生效的配置周期，不是实际切图完成间隔，也不保证任何大小文件都能按这个间隔完成。

当前已有图片预读取，不能再次称“新增预读”。rtl/image/sd_card_bmp.v通过auto_half_due_q（sec_cnt >= auto_period_sec >> 1）等待周期过半才触发PF_IDLE到预读。2秒档约到1秒才开始，3秒档整数右移也约到1秒。其他条件包括bmp_ready、!load_busy、!switch_lock、!vid_lock及多张图片。

该限制历史上用于防止图片读卡饿死音乐，不能简单删去保护。当前顶层image_priority_q也参考音频fifo_usedw[13]，但其存在不能单独证明提前预读后不会饿死音频。

到期切图仍等待图片准备完成及转场/显示缓冲交接。fade_in的LVL_MAX=17，淡出/淡入每帧推进；720P60下每段约0.28秒，整段约0.57秒量级，实际握手时间需要测量。缩放始终生成1280×720完整输出帧，因此即使源图很小，也存在输出写入成本。

用于理解的一阶近似（不是已测指标）：忽略其他阻塞时，若预读在t_pre开始，准备耗时T_prepare，切换可开始时刻约max(P,t_pre+T_prepare)，随后还有淡出/缓冲交换等等待。当前t_pre约floor(P/2)，提前预读可减少人为等待，但不能超越持续读卡和输出写帧吞吐上限。

## 推荐顺序

1. 先测阶段耗时：从请求到首SD字节、SD读结束、解码结束、写帧完成、PF_DONE、淡出请求/完成和显示银行切换。用仿真计数先定位，再以可关闭的硬件计数或采集卡验证；记录音频FIFO最低水位和欠载事件。覆盖大/小BMP、QOI、碎片簇链、最短周期和连续按键。
2. 音频水位允许时尽早预读：在当前图已提交且缓冲安全后启动下一张，按高低水位让出SD读取机会，仅在完整物理事务/扇区安全边界交接，避免打断CMD18。先复用现有缓冲，不新增BRAM。手动跳图/进出视频/预读失败需能撤销过期目标，不能破坏显示银行所有权。
3. OSD区分设定与等待：保留AUTO间隔；到点而未准备好时显示LOAD/等待，准备完成显示READY或小图标。这样避免“设成2秒就一定2秒完成”的误解。不要伪造精确剩余秒数。
4. 可选短转场/硬切：适合展示或快速浏览，可减少感知等待；只在下一图完整写好并到安全帧边界时切换，不展示半帧。它不提高读卡带宽。
5. 配套工具按目标做素材优化：屏幕最多呈现1280×720，超大图片可预处理至足够的有效分辨率；比较BMP快速跳行与QOI，QOI不保证更快，复杂照片可能压缩收益低、解码成本高。保留高/低原图清晰度差异的赛题样本，不能把所有验收图预处理成相同分辨率。

## 其他资源利用

R3 LUT18221/19600（余1379），Slice9389/9800（余411），BRAM9K仅余1，BRAM32K已满，DSP余7。独立setup+0.301ns、hold+0.024ns，不能把空余LUT视作能无代价加入的大模块。先调度和小型状态显示，再考虑频谱快起慢落/幅度映射的共享运算；暂不优先扩大FFT、复制帧缓存或贸然提高SPI时钟。

每项变更必须保留R3回退，逐像素/状态切换回归，最终新进程生产SDC检查全部9时钟和HDMI同步路径，再上板。目标是已知样本的短周期更接近设定值，不能承诺任意文件固定2秒完成或未经测量的倍数提速。
