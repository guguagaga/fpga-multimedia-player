# 算法与设计思路

## 视频：把复杂搜索放在离线端

Codec8/9 将 RGB565 帧划分为 8×8 块。解码器识别实色块 `0x80`、双色全块掩码 `0x81`、原始 RGB565 `0x83`、四个 4×4 象限各有一个代表色的 `0x84`，`0xff` 结束一帧。Codec10 增加 `0x85` 连续实色块，最多一次表示 256 块；不改变重建像素。

离线编码器为每块比较候选表示，在帧字节预算下分配细节；复杂纹理优先消耗预算，平坦区域可用实色或双色表示。生产编码器使用 RGB565 原生通道上的 `4ΔR²+ΔG²+4ΔB²` 误差，使5/6/5位通道的尺度更接近一致，双色候选从分位点、极值等5组初值最多迭代8次，再构造率失真下凸包，以每增加一字节减少的误差分配预算。AMBTC 的绝对矩统计给代表色提供初始化研究思路，S2TC 的颜色距离、候选搜索与细化给离线优化提供参考。它们不是生产 RTL 中两个额外解码器。当前生产行为以 `host/video/src/encode_720p.cpp` 为准，研究中未进入此文件的策略仍属于实验。

这种方法使画质搜索可迭代，而硬件保持有限几类 token 解码。受限于块表达能力、RGB565 量化、带宽和帧预算，复杂游戏画面仍可能有块感。增加预算主要增加 RAW/更细候选的机会；提升帧率则减少每帧可用传输时间，二者必须一起评估。

块流进入 `video_codec8_block_decoder` 后按块生成像素，`video_codec8_raster` 与视频缓存重排为行流，再由 SDRAM 写侧提交完整帧。文件头支持某帧率不代表整机可在任何素材下持续达到该帧率。

## 音画同步

`av_sample_sync` 以实际消费的 PCM 样本计时。新显示缓冲授权一帧的音频预算；48kHz 下 15/20/25/30fps 对应 3200/2400/1920/1600 对样本，当前720P顶层提前1920对样本（40ms）授权下一视频帧；`av_sample_sync`模块默认960，生产实例显式覆盖。读卡慢时预算耗尽会等待并短暂静音，避免音频持续领先。暂停停止正常消费；切换旧流排空使用独立条件。该策略限制漂移但不能提高物理吞吐。

## 快速 BMP

现有最近邻缩放只使用 `floor(y*H/480)` 对应源行。当 H 为 960/1440/1920 时，所需源行恰好为 0,N,2N,…,479N。v19 直接请求与这些行相交的 SD 扇区，仍完整接收在途扇区，再丢弃不属于目标行的字节。宽为 640…4096 且 4 对齐，像素偏移小于 65536 字节时启用；其它情况走原路径。

地址、行尾与下一行位置预先寄存，避免将宽乘法/多级地址选择放进关键路径。报告给缩放器的有效高度为 480，但源数据边界必须按原始宽高计算。扇区与行不对齐会产生重复读取或部分浪费，因此节省不能简单等同于 1/N。

CMD17 收完数据和 CRC 后直接结束；CMD18 仍使用 CMD12 和排空。顶层图片已使用 CMD18 缓存，所以不能将 CMD17 单次提速倍数当作所有图片的整机提速倍数。

## QOI、QOA、IMA 与频谱

QOI 使用 INDEX/DIFF/LUMA/RUN/RGB/RGBA 等无损命令，RTL 先缓存完整扇区再展开像素，支持回压与结束标志检查。QOI 明确排除 BMP 跳行，不破坏其压缩流状态。

QOA 使用四阶 LMS 预测与量化残差，RTL 时分复用预测/更新运算并用同步 RAM 存权重；IMA ADPCM 使用 step/index 表逐样本重建，ADPCM-XQ 的前瞻和噪声整形仅发生在离线编码端，输出仍是标准 IMA WAV。

音乐切换执行淡出、静音确认、读取器切换、新曲就绪、渐入；并非双路 crossfade。频谱采用 256 点 periodic Hann 和 FFT；幅值补偿约 2 倍并饱和，Hann 只作用于可视化输入，不改变播放音频。

图片浅横线修复关闭了频谱层默认参考网格，保留柱状频谱。硬件缺陷定位及板测边界见验证文档。

QOI生产实例设置`BRAM32_INDEX=1`，颜色索引低/高16位存到同一BRAM32K的两个地址区，原同步读时序保持不变。通用模块默认保留推断存储。它是存储实现调整，QOI仍无损；共享BMP/QOI尺寸乘法和有界余数运算同样不改变图像采样坐标。详见[TIMING_OPTIMIZATION.md](TIMING_OPTIMIZATION.md)。

后续无损RAW范围位打包探索见[RAW_BOUNDS_RESEARCH.md](RAW_BOUNDS_RESEARCH.md)。实验opcode0x86当前RTL不支持，未写入SD卡。
