# v182 载荷连续读取修改说明

本轮以 v180 为基线，仅修改三个 SD 模块。目标是减少相同 SPI 时钟下的数据字节间空闲，为既有视频/音频链路提供读卡余量。

| 模块 | 本轮职责变化 | 保留行为 |
|---|---|---|
| SD/sd_card_cmd.v | 在数据块有效载荷读取状态产生 read_stream，临近最后一个字节撤销连续读许可 | 命令、找令牌、CRC字节消费、停止命令、清理及错误状态 |
| SD/spi_master.v | 在许可有效且 clk_div=0、CPOL/CPHA均为1时，末位后直接进入下一字节，并产生单周期 stream_ack | 原字节握手作为回退路径；低速初始化、命令和写入路径 |
| SD/sd_card_top.v | 连接命令层与SPI字节层的 read_stream | 仲裁、缓存接口和对外引脚 |

## 时钟与握手

系统核心约90.909MHz、SPI边沿约22.727MHz，未提高时钟。普通字节路径在最后一个采样边沿后还会经过结束、确认、确认等待和空闲状态。载荷连续路径把字节间多余状态去掉；主要载荷间隔由36核心周期缩短到32周期，边界仍保留原握手。

只有已经接受读取令牌后，确定要收满512字节的载荷部分使用连续路径。读过程MOSI始终送0xFF。命令字节和任意可变数据不能直接套用此快速路径。输出确认与MISO移位数据的周期对应关系由引脚级测试逐字节核对。

CRC字节仍被消费，不表示本次新增CRC校验。CMD18收尾仍发送CMD12并保留600字节清理；没有把这项历史兼容处理删掉。突发仍为16扇区，缓存容量没有增加。

## 为什么要配套新媒体

原高码率Codec10影片平均占用过多读卡时间。仅约10%的事务吞吐改善，仍不足以为该影片、PCM音频和FAT访问同时提供稳定余量。配套Codec12 Q125全片保持720P15，使用已有EDGE/PAL4等表示和相同纯色块无损打包，把整片从984333824字节降低到738020352字节。

该编码仍是独立帧、块内近似表示，没有加入帧间预测、软核或新解码指令。v180本来已能识别这些Codec12指令。本轮比特流的区别是读取效率，媒体文件的区别是编码表示和数据量；二者不能混为一谈。

## 验证与限制

- 真实CMD/SPI RTL的引脚级测试覆盖CMD17、CMD18单块/16块、CMD12、初始化、缓存命中、并发仲裁、取消和命令错误恢复。
- 连续播放模型包含实际FAT/缓存/仲裁/视频解码/块转行/写帧控制/音频读取，核对像素、写地址和PCM；物理卡、内存接收和PCM消费部分为模型。
- 真实音频同步器、采样构造器、I2S独立验证了稳定供帧和迟帧控制。
- 功能结论与原SDC下独立布线时序结论分开记录。不能以数据正确替代连续性，也不能以内部STA通过替代真实卡和显示器验收。
