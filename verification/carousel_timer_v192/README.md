日期：2026-11-01。基线为 R3（Git b2d6102），工作分支 `fix/carousel-timer-v192`。seed24 已通过独立内部 STA，上板验收尚未进行。

## 修正内容

1. 保留原计时器结构，将重新计时和显示银行提交的清零放到最终计数分支的最高优先级，防止同拍计数更新覆盖清零。
2. 使用实际显示银行提交事件作为新图片的计时零点和新拨码周期的生效边界。后台预读完成、读图失败均不属于显示提交。
3. 重新计时、视频锁定、已挂起转场和图片错误期间不发出新的自动切图请求。发出的自动请求解除到期标志，显示提交时再次清零，因此读取迟到不会缩短下一张的等待时间。
4. QOI 新启动边沿屏蔽上一张的完成/错误标志，修复连续 QOI 加载提前结束的问题。

顶层已经使用 `SD_CORE_HZ=90_909_091` 换算秒数。本次没有修改系统时钟，也未增加时序例外。保留半周期预读策略及原音频仲裁策略。

## 设置周期的含义

设置值是从图片银行提交到允许发起下一次转场的目标等待时间。准备充分时，到点开始淡出，淡出结束后提交下一张。因此相邻图片提交间隔还包括淡出时间；内存扫描在帧边界采纳新银行，也有帧边界/CDC 延迟。大图读取未及时完成时会继续显示当前图片，随后从新图提交重新计时。

轮播中改变拨码，新值从下一张提交时生效；关闭轮播时直接跟随拨码。按 D 重新计时使用当前已生效的周期，不强制采纳尚未到边界的新拨码值。已经开始的转场按原握手完成。
